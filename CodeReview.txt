HIGH SEVERITY


[H1] classical_news backend always fails on organizations/locations  (CONFIRMED)
  Location: KnowledgeGraphApp/Extraction/ClassicalNews.py:32-37, KnowledgeGraphApp/WebApi/Schemas.py:104-111,
            KnowledgeGraphApp/ExtractionPipeline.py:564-567, KnowledgeGraphApp/GraphStorage/GraphBuilder.py:223-225, KnowledgeGraphApp/TypeMapping.py
  Problem:  TYPE_MAP emits "ORGANIZATION" and "LOCATION". ResolvedEntityPayload only
            allows {CONCEPT, PERSON, ORG, GPE, PRODUCT, EVENT, LAW, DATE, MONEY}.
            run_pipeline_write validates every entity, so a ValidationError is raised.
            Even if validation passed, write_entities skips types missing from TYPE_TO_LABEL,
            so the entities would never be written and their edges would silently vanish.
  Failure:  RELATION_BACKEND=classical_news + any text with an organization or location
            -> job status "failed" with a pydantic ValidationError.
  Fix:      Map to internal types in TYPE_MAP: ORGANIZATION -> ORG, LOCATION -> GPE, and
            update VALID_TYPE_PAIRS to match. Alternatively add the labels to TYPE_TO_LABEL,
            but one internal vocabulary is preferable. Add an integration test that runs
            run_pipeline_write (with a mocked session) on classical_news output.

[H2] classical_news chunk IDs do not match Chunk nodes  (CONFIRMED)
  Location: KnowledgeGraphApp/ExtractionPipeline.py:160, 189, 243
  Problem:  Entity/edge chunk_ids are built as f"{job_id}:{stanford_sentence_idx}".
            Chunk nodes are written with f"{doc_id}:{spacy_sentence_idx}" (Preprocessor.py:126).
            Prefix differs (job UUID vs document SHA-256) and sentence indexes come from two
            different splitters.
  Failure:  1) write_mentions MATCHes no Chunk -> no MENTIONED_IN edges.
            2) Every doc_id filter (`cid STARTS WITH $doc_id + ':'`) in QueryEngine.py and
               clear_document misses these edges.
            3) Re-ingesting the same file never clears old edges/entities; each upload gets a
               new job_id, so duplicates accumulate. doc_id-scoped stats/visualization show 0.
  Fix:      Always prefix with preprocessed.doc_id. Build chunks from the same sentence
            boundaries the extractor uses (as SvmPipeline.py does), or map Stanford
            character offsets onto the spaCy chunk that contains them.

[H3] Unauthenticated endpoint deletes the entire graph  (CONFIRMED)
  Location: KnowledgeGraphApp/WebApi/Routes/GraphRoutes.py:85-95, KnowledgeGraphApp/WebApi/App.py:48-53
  Problem:  DELETE /api/graph/clear has no require_api_key dependency. CORS allows "*"
            for all methods, so any web page the user visits can call it.
            "MATCH (n) DETACH DELETE n" also runs as one transaction (memory risk on large graphs).
  Failure:  API key configured; anonymous `curl -X DELETE http://host/api/graph/clear`
            wipes all documents, entities and edges.
  Fix:      Add dependencies=[Depends(require_api_key)] (consider on all routes). Restrict
            allow_origins via a settings field. Delete in batches
            (CALL { ... } IN TRANSACTIONS OF 10000 ROWS) or document the limitation.

[H4] Stanford bridge timeouts are never enforced  (CONFIRMED)
  Location: KnowledgeGraphApp/Extraction/StanfordClient.py:65-66, 153, 185
  Problem:  request_timeout is stored but unused. proc.stdout.readline() blocks with no
            timeout, so startup_timeout is also ineffective if the JVM prints nothing.
            The response "id" is not checked against the request id.
  Failure:  Bridge hangs (GC thrash, deadlock) -> annotate() blocks forever inside the single
            ThreadPoolExecutor worker while holding the pipeline file lock -> every later job
            stays "running"/"queued" until the server is restarted.
  Fix:      Read stdout on a reader thread into a queue and use queue.get(timeout=...), or use
            selectors on the pipe. On timeout: kill the process, reset self.proc, raise
            TimeoutError. Verify resp["id"]  rid.

[H5] YAML config overrides .env and bypasses validation  (CONFIRMED)
  Location: KnowledgeGraphApp/Settings.py:50-69
  Problem:  Precedence check uses `k.upper() not in os.environ`. Values loaded from .env by
            pydantic-settings are not in os.environ, so YAML silently overwrites them.
            setattr() on a BaseSettings without validate_assignment skips type/Literal checks.
  Failure:  .env sets RELATION_BACKEND=semeval_svm, Settings.yaml sets rules -> rules is used.
            Settings.yaml sets relation_backend: "typo" -> accepted; pipeline silently falls
            through to the rules backend.
  Fix:      Implement settings_customise_sources() with a YAML source placed after env and
            dotenv sources, or merge YAML first and construct Settings(**merged) so validation
            runs. Use self.model_fields_set / explicit source tracking for precedence.



MEDIUM SEVERITY


[M1] Upload request performs full extraction (including OCR) synchronously  (CONFIRMED)
  Location: KnowledgeGraphApp/WebApi/Routes/IngestRoutes.py:68-70, 84
  Problem:  _sample_text calls load_document on the whole file only to keep 3,000 chars.
            For scanned PDFs this OCRs every page at 300 DPI inside the HTTP request, then the
            pipeline does it all again. Thread-pool workers are not bounded by the pipeline lock.
  Failure:  A 50 MB scanned PDF holds the request for minutes; several uploads in parallel
            exhaust CPU and the Starlette threadpool.
  Fix:      Sample only the first N pages/paragraphs for language detection, or move the
            language gate into the background job and report it via job status.

[M2] v2 claims are never written to the intermediate graph  (CONFIRMED)
  Location: KnowledgeGraphApp/ExtractionPipeline.py:577-584 (vs. parameters at 53-61)
  Problem:  _write_intermediate_graph accepts claims/canonical_claims, but run_pipeline_write
            never passes nlp_result["v2_claims"] / ["v2_canonical_claims"].
  Failure:  contextual_v2 and classical_news runs produce Datasets/Processed/<doc>.json with
            "claims": [] and "canonical_claims": [] even when claims exist.
  Fix:      Pass claims=nlp_result.get("v2_claims"), canonical_claims=nlp_result.get(...).

[M3] semeval_svm path bypasses preprocessing applied to every other backend  (PLAUSIBLE)
  Location: KnowledgeGraphApp/ExtractionPipeline.py:138-140, KnowledgeGraphApp/Extraction/SvmPipeline.py
  Problem:  Returns before preprocess(), so no NFKC normalization, no whitespace collapse and
            no in-pipeline language gate. Character offsets and entity text differ from the
            same document processed by other backends.
  Fix:      Apply normalize_text() before annotation (offsets then refer to normalized text,
            matching other backends), or document the intentional difference.

[M4] Error handling inconsistent across read routes  (CONFIRMED)
  Location: KnowledgeGraphApp/WebApi/Routes/SearchRoutes.py:14-25, KnowledgeGraphApp/WebApi/Routes/GraphRoutes.py:35-49, 98-105
  Problem:  /api/search and /api/graph/hubs have no try/except (500 with stack trace when
            Neo4j is down). /api/graph/path swallows all errors and returns [] which is
            indistinguishable from "no path". Empty or whitespace q produces a Lucene parse
            error -> 500. source  target makes shortestPath raise.
  Fix:      Return 503 on driver errors for all routes; validate q with min_length=1 and
            strip(); short-circuit source  target.

[M5] Visualization can return up to 2x the requested node limit  (CONFIRMED)
  Location: KnowledgeGraphApp/GraphSearch/QueryEngine.py:165-179
  Problem:  The isolated-node query applies LIMIT $limit independently of the edge query.
  Fix:      Only fetch isolated nodes for the remaining budget (limit - len(nodes_dict)),
            and skip the query when the budget is 0.

[M6] clear_document scans every relationship on each ingest  (CONFIRMED)
  Location: KnowledgeGraphApp/GraphStorage/GraphBuilder.py:145-157
  Problem:  MATCH (a:Entity)-[r]->(b:Entity) with a list predicate has no index support,
            so ingest cost grows with total graph size.
  Fix:      Start from the document's chunks/entities
            (MATCH (c:Chunk {doc_id:$doc_id})<-[:MENTIONED_IN]-(a)-[r]->(b)) and dedupe r,
            or maintain a doc_ids list property with an index.
